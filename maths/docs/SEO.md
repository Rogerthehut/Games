# Findability: search engines, feeds and AI assistants

Everything public is plain HTML, generated at build time from the same data the app uses, so it can't drift.

## What's in place

| What | Where |
| --- | --- |
| Home page title, description, share image, structured data (Organization, WebSite, WebApplication) | `index.html` |
| Parent guides and FAQs | `scripts/parent-pages.ts`, `src/parents/content.json` |
| Study guides (`/learn/`), kept out of search on purpose: `noindex`, not in the sitemap or llms files, not linked from public pages | `scripts/concept-pages.ts`, `src/concepts/library.ts` |
| Free practice paper page (`/curriculum/practice-paper.html`) and its PDF (`/quarter-sample-practice-paper.pdf`) with a first-page picture, rebuilt with `npm run paper-sample` | `src/ui/print-paper.tsx`, `scripts/build-paper-sample.ts` |
| Free booklet sample page (`/curriculum/booklet.html`) and its PDF (`/quarter-curriculum-sample.pdf`), rebuilt with `npm run booklet` | `src/booklet/model.ts`, `scripts/build-booklet.ts` |
| What quarter covers (`/curriculum/`: one page per year, plus the STEM lab) | `scripts/site-pages.ts`, built from the curriculum |
| Blog (`/blog/`) and its RSS feed (`/blog/rss.xml`) | `src/blog/posts.ts`, `scripts/site-pages.ts` |
| Reading list (`/reading/`) | `src/blog/reading-list.json`, filled by `npm run reading-list` |
| Sitemap (`/sitemap.xml`) | generated by `scripts/site-pages.ts`: it lists every public page and takes dates from the content |
| Long plain-text guide for AI assistants (`/llms-full.txt`: topics by year, the STEM lab, the blog, parent guides and the 11+ test notes for every area with their sources and how sure we are), short one (`/llms.txt`) | generated and `public/llms.txt` |
| `robots.txt` (allows everything except `/api/` and `/ops`; the ops page also sends `noindex`), `/.well-known/security.txt` | `public/` |
| Icons: `favicon.ico`, 16, 32, 180 (Apple), 192, 512 and a maskable 512, plus the web manifest | `npm run icons` redraws them from `public/icon.svg` |

The booklet PDF, the learning app and the account pages are deliberately not in the sitemap.

## Adding and updating content

- **A new article:** add an entry to `src/blog/posts.ts` (slug, title, description under 175 characters, date, body, related links). The page, the feed, the sitemap and `llms-full.txt` all update on the next build.
- **The reading list:** run `npm run reading-list` on a machine that can reach the feeds in `src/blog/sources.ts`, read through `src/blog/reading-list.json`, delete anything that isn't suitable, and commit it. Only the title, link, date and a short excerpt are kept, and each item links to the original. A feed that can't be reached keeps its earlier items.
- **Sitemap dates:** `CONTENT_DATE` in `scripts/site-pages.ts` is the review date for the pages built from data. Change it when something worth telling crawlers about has changed. Each article uses its own date.

## Before submitting to search engines

1. **Check the live site.** Open `/sitemap.xml`, `/robots.txt`, `/blog/rss.xml` and `/llms-full.txt` on the real domain, and view the source of a few pages. Canonical links should show `https://yourquarter.co.uk/...`.
2. **Google Search Console.** Add a *Domain* property for `yourquarter.co.uk` and verify it with the DNS TXT record Google gives you (this covers every subdomain and protocol, and needs no change to the site). Then open Sitemaps and submit `https://yourquarter.co.uk/sitemap.xml`. Use URL Inspection on the home page and one article, and choose Request indexing.
3. **Bing Webmaster Tools.** Sign in, and use Import from Google Search Console to bring the site across with its sitemap. Bing also feeds DuckDuckGo and several AI assistants.
4. **IndexNow (optional).** Bing, Yandex and others accept instant notifications of new or changed pages. Generate a key in Bing Webmaster Tools, serve it at `/<key>.txt`, and ping `https://api.indexnow.org/indexnow?url=<page>&key=<key>` after publishing a new article.
5. **Check structured data.** Paste a blog page and a curriculum page into Google's Rich Results Test. Articles use `BlogPosting`, curriculum pages use `ItemList`, and every page has a breadcrumb trail.
6. **Check the share image.** Paste an article link into a messaging app or a social post preview to confirm the title, description and image appear.
7. **Feed.** Add `/blog/rss.xml` to a feed reader to confirm it loads and shows the articles in order.

## Ongoing

- Publish an article every week or two. Fresh, useful pages matter more than any tag.
- Link from articles to the matching curriculum page or parent guide. Study guides are deliberately not linked from public pages or indexed.
- Look at Search Console's Performance report monthly. Queries that show impressions but few clicks are a good source of article ideas.
- Keep titles under 60 characters and descriptions under 160 where possible. The tests enforce hard limits.
- When a topic is added to the app, rebuild the booklet (`npm run booklet`) so the PDF matches.
- If the print layout of a paper changes (`src/ui/print-paper.tsx`, the `.pp-` styles) or the maths questions change a lot, rebuild the sample paper (`npm run paper-sample`).

## Subscribing to the blog

People are sent to `blog/subscribe.html`, a readable page with reader buttons and a copy box, not to the raw feed. The feed `blog/rss.xml` is for apps and is plain XML: it has no XSLT stylesheet, because browsers are removing XSLT support (Chrome shows a warning on pages that use it). Every link meant for a person (the footer, the blog page) goes to the subscribe page. Feed discovery is unchanged: every public page still has the `<link rel="alternate" type="application/rss+xml">` tag, so readers and crawlers find the feed.
